## Questions I expected M0 to answer

**1. Why is the first token slower than the rest?**
Before any token can be produced, the whole prompt must be processed (prefill) to build the KV cache. That work scales with prompt length: here about 275 ms for a ~90-token prompt and 2.3 s for ~550 tokens. After that, each token only needs one decode step, which took a steady ~12 ms. So TTFT depends on the prompt, while ITL depends on the model and hardware.

**2. Is a 1.5B model at 4-bit usable on a laptop CPU?**
Yes. 84 tokens/s is faster than reading speed, and a 200-token answer takes ~2.5 s. The limit is the prompt side: prefill at ~235 tokens/s means long prompts are noticeably slow, and each slot only holds 2048 tokens of context.

**3. What will the gateway have to get right that a plain proxy would not?**
- Measure TTFT at the first *content* token, not the first SSE event (the server sends an empty role event immediately).
- Pass through or translate the context-overflow 400 error.
- Keep benchmarks honest about prompt caching.

## Baseline (5 measured runs after 1 warm-up, unless noted)

| Measure | Value |
|---|---|
| Decode speed | ~84 tok/s; ITL median 11.9 ms, p95 12.9 ms |
| Prefill speed | ~235 prompt tok/s (548 tokens in 2.34 s) |
| TTFT, ~90 prompt tokens (unique prompts) | median 274 ms (range 274–289) |
| TTFT, ~550 prompt tokens (unique prompts) | median 2340 ms (range 2236–2379) |
| TTFT, repeated identical prompt | ~16 ms, due to the prompt (KV) cache, so not representative |
| 200-token answer, end to end | 2.46 s |
| Over-long prompt (6419 tokens) | HTTP 400 `exceed_context_size_error` (slot limit 2048) |

**Caveat:** single client, one request at a time, small sample. This characterises the model server alone; concurrency behaviour is measured in M5.

## Interview angle

Prefill is compute-bound and parallel across prompt tokens; decode is memory-bandwidth-bound and sequential. So long prompts hurt TTFT, long answers hurt total latency, and a throughput number alone hides both. That is why Crucible exports TTFT and ITL as separate histograms.
